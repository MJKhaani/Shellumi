# Initial threat model

This document is preliminary; no security-sensitive Shellumi subsystem has
been reviewed or approved for production. Revisit it with each design change.

| Threat | Required control | Current status |
| --- | --- | --- |
| Host-key substitution | Verify known keys; explicitly confirm unknown keys; reject changed or revoked keys | System OpenSSH launched with `StrictHostKeyChecking=ask`; pure Rust `known_hosts` verification engine (`shellumi-core::known_hosts`) implements strict matching, TOFU detection, changed-key MITM risk alerts, and `@revoked` key rejection with automated tests |
| Stolen local or synced data | OS-protected keys and authenticated encryption; no plaintext secrets or sync | Credential abstractions include macOS Keychain and encrypted file storage; Windows and Linux native stores are not implemented. Secure secret entry and real cloud sync remain outstanding. |
| Malicious terminal output | Bound resource use; gate clipboard, hyperlinks and unsafe control sequences | Implemented: `shellumi-terminal` parses VT/ANSI with strict bounds; OSC sequence sanitization strips ASCII control codes (`\x00..\x1F` except tab) and clamps window titles to 256 characters; configurable scrollback capacity (`DEFAULT_SCROLLBACK_CAPACITY` = 10,000) with automatic line trimming prevents memory exhaustion; stress tests verify large output workloads |
| Untrusted host configuration | Validate persisted and imported records; pass process arguments separately | Core validates destinations; CLI and GPUI dispatch to OpenSSH with explicit argv, `--`, and no shell evaluation |
| Malicious imports or filenames | Validate structure, size and paths; avoid shell interpretation | RFC 4180 CSV and OpenSSH client config parsers validate all destination fields, enforce structure limits, and reject invalid records without shell evaluation |
| Accidental service exposure via SSH tunneling | Warn on public/wildcard bind addresses before creating forwarded ports | Port forward rules check `is_exposed_beyond_localhost()`; CLI emits explicit security warning when binding to non-localhost addresses; default binding strictly 127.0.0.1 |
| Directory traversal, malformed packets, or unsafe file writes in SFTP | Normalize paths, validate breadcrumb navigation, reject null bytes and control characters, enforce conflict resolution, validate packet framing and length bounds | `PathUtils` normalizes `..` components and prevents path escapes; transfer paths reject empty strings and control characters; transfers record audit history in database; conflict strategies (overwrite, skip, rename) defined; RFC SFTP v3 wire protocol enforces strict packet length validation (max 16 MB DOS limit, zero-length packet rejection), stream framing, and bounds-checked safe wire reading (`WireReader`) |
| OAuth token theft, sync replay, and ciphertext transposition | Protected tokens, state validation, authenticated versioned records, unique nonces, and bound associated data | Implemented: RFC 7636 PKCE code challenge and CSRF state validation in `shellumi-core::sync`; ephemeral loopback OAuth callback listener (`OAuthCallbackListener`) with token expiration checking (`OAuthTokenBundle`); secure token persistence in OS credential stores (`OAuthTokenBundle::save_to_store`, `load_from_store`, `delete_from_store`) preventing plaintext disk leakage; zero-knowledge AES-256-GCM authenticated encryption envelopes with unique salt and nonce per record; bound associated data (`entity_type:object_id`) preventing record transposition attacks; incrementing version counters and deletion tombstones with three-way conflict detection (`determine_sync_action`); payload-decrypting difference engine (`diff_sync_records_with_passphrase`); PBKDF2-HMAC-SHA256 key derivation with memory zeroization on drop |
| Unsafe automation and snippet injection | Preview and explicit confirmation; isolate secrets and validate substitution | Implemented: `prepare_startup_snippet` validates templates, isolates variables (`{{host.*}}`), and screens for destructive commands (`check_dangerous_command`); `StartupSessionTracker` enforces policy gating (`AutoAfterAuth`, `RequireConfirmation`, `Disabled`); multi-host batch execution (`shellumi-core::batch`) enforces POSIX escaping, target variable isolation, and dry-run previews |
| Command palette action hijacking or injection | Typed action enum dispatch; decoupled scoring; no shell evaluation of query strings | Implemented: `PaletteAction` is a strictly typed Rust enum; query strings are evaluated solely for ranking and never executed in a shell; all actions map to explicit internal Rust methods; multi-host batch execution (`shellumi-core::batch`) validates target properties, enforces POSIX escaping, provides dry-run previews, and isolates target variables |
| Accidental data loss during sync or remote corruption | Automated local disaster recovery snapshots, retention limit pruning, and snapshot rollback | Implemented: `sync_snapshots` table (schema version 7); automatic pre-import and export snapshot creation (`archive_snapshot`) with configurable retention (default latest 3 snapshots); CLI subcommands `vault history` and `vault rollback <snapshot-id> [--passphrase <p>]` allow instant restoration of local records from archived snapshots |
| Unauthorized collaboration and shared vault privilege escalation | Role-based access control, cryptographic epoch rotation, single-active-writer keystroke arbitration with immediate host revocation, and tamper-evident append-only audit trail | Implemented: Role hierarchy (`Owner`, `Administrator`, `Editor`, `Viewer`) with strict capability boundaries (`shellumi-core::collaboration`); shared vaults with key-rotation epochs (`rotate_key()`) preventing revoked members from decrypting future epochs; multiplayer terminal sharing enforces single active writer (`active_writer_id`) with immediate session-owner override (`revoke_keyboard_control`) and non-controller keystroke suppression; tamper-evident audit logging for all vault, member, role, and terminal operations (`sharing_audit_log`); clear disclosure that revocation does not erase previously cached historical records |
| Predictable vault encryption key | Require a user-supplied secret and protect its entry | Implemented: CLI and desktop vault sync operations require user-supplied passphrases and reject empty secrets. Zero-knowledge AES-256-GCM encryption with PBKDF2-HMAC-SHA256 key derivation and memory zeroization. Full sync cycle (`execute_sync_cycle`) enforces interactive three-way conflict review, side-by-side local vs remote diff inspection, and pre-sync snapshot backups. |
| Startup command sent into an authentication prompt | Wait for verified session readiness and inspect commands before execution | Implemented: `StartupSessionTracker` monitors the PTY output stream for session readiness; suppresses auto-dispatch during password, passphrase, and MFA challenges (holding status in `PendingAuth`); transitions to `ReadyToDispatch` upon encountering shell prompts or OSC 133 prompt markers (`133;A` / `133;B`). |
| Incorrect jump-host dispatch | Validate jump chains and place SSH options before the destination | CLI and GPUI use a shared validated argument builder; real jump-host testing remains outstanding. |
| Accidental destructive execution via multi-pane broadcast input | Intercept dangerous commands before execution; provide explicit exclusion controls; visual indicators | Implemented: `BroadcastManager` requires explicit user opt-in (`📡 Broadcast: ON`); high-visibility red status pill indicates active typing mirroring; each pane has an independent exclusion toggle (`[🔇 Excluded]`); `check_dangerous_command` screens buffer input and paste text for destructive commands (`rm -rf /`, `mkfs`, `dd of=/dev/`, fork bombs, `shutdown`, `reboot`, `iptables -F`) and blocks dispatch across broadcast terminals with a prominent warning banner |
| Cleartext Telnet credential and traffic interception | Enforce prominent warnings; restrict SSH-only capabilities; disallow silent fallback | Implemented: `TelnetConfig::security_warning()` emits explicit warning in CLI `show <id>`, `connect <id>`, and `telnet <host>`; desktop `HostForm` displays high-visibility warning banner (`⚠️ UNENCRYPTED PROTOCOL`); terminal tab header displays persistent `[⚠️ UNENCRYPTED TELNET]` badge; SFTP, jump host chaining, and port forwarding are strictly prohibited on Telnet targets |
| Serial line access misconfiguration or command injection | Validate communication parameters, isolate from network tunnels, and require explicit local device paths | Implemented: `SerialConfig` validates baud rate, data bits, parity, stop bits, and flow control; `discover_serial_ports()` filters local device candidates (`/dev/tty.*`, `/dev/cu.*`, `COM*`); CLI and GPUI isolate serial sessions from remote network tunnels, jump hosts, and startup snippet auto-execution |
| Mosh UDP firewall exposure and argument tampering | Validate UDP port boundaries, prediction modes, and server binary path | Implemented: `MoshConfig` enforces UDP port range validity (1..=65535, start <= end), validates prediction mode enum, checks destination parameters, and prevents shell interpretation during argument construction |
| Cloud infrastructure credential disclosure and malicious discovery injection | Redact credentials in logs/summaries, enforce least-privilege scoping, validate imported host parameters, prevent inventory overwrite attacks | Implemented: `CloudProviderConfig::redacted_summary()` masks AWS secret keys, Azure client secrets, and DigitalOcean API tokens; `AwsEc2Parser`, `AzureVmParser`, and `DigitalOceanParser` sanitize IP addresses, ports, and instance identifiers; `InventoryMergeEngine` applies non-destructive reconciliation policies (`MergePolicy::PreserveExisting`, `MergePolicy::UpdateExisting`) to prevent dynamic discovery runs from wiping user-created tags, notes, or assigned credentials; foreign keys in `discovered_hosts` track imported IDs against `hosts(id)` |
| Cryptographic degradation, compromised dependencies, or release binary tampering | Automated health diagnostics and runtime verification, Software Bill of Materials (SBOM) and cryptographic release checksums | Implemented: `shellumi-core::diagnostics` verifies CSPRNG entropy (`ring::rand::SystemRandom`), tests AES-256-GCM AEAD encryption/decryption round-trip, audits OpenSSH binary discovery, and checks loopback socket binding; CLI `doctor` and desktop Diagnostics Modal report system health status and remediation advice; GitHub Actions release pipeline automatically generates CycloneDX SBOM and SHA-256 checksums (`SHA256SUMS.txt`) |
| Mobile background memory retention & socket termination | Proactively drop plain socket descriptors and zeroize memory upon background expiration; deterministic reconnection backoff | Implemented: `MobileLifecycleManager` enforces bounded grace period (default 30s matching iOS `beginBackgroundTaskWithExpirationHandler`); upon `BackgroundExpired` or `NetworkLost`, session transitions to `Suspended` and zeroizes sensitive state; foregrounding invokes exponential reconnection backoff |
| Unauthenticated mobile credential access on lost/stolen device | Hardware-backed biometric authentication (Secure Enclave / StrongBox Keystore) enforced on each key unlock | Implemented: `MobileCredentialSpec` requires `kSecAccessControlBiometryAny` on iOS (Face ID / Touch ID) and `setUserAuthenticationRequired(true)` with StrongBox on Android; no credentials stored in unencrypted mobile app storage |
| Mobile virtual key interception / third-party keyboard telemetry | Terminal accessory bar renders native buttons directly, bypassing third-party software keyboard event streams | Implemented: `VirtualAccessoryBar` maps touch keystrokes directly to raw ANSI escape bytes in Rust memory, without broadcasting keystrokes through system text input notifications or third-party keyboard extensions |
| Insecure credential auto-injection into fake or intercepted terminal prompts | Restrict prompt detection to passive identification; never auto-inject passwords, private keys, or tokens without interactive user confirmation | Implemented: `PasswordPromptDetector` strictly restricts prompt detection to passive classification (`Sudo`, `Ssh`, `KeyPassphrase`, `MfaCode`, `GenericPassword`) for user awareness and UI badge presentation; credentials are NEVER automatically transmitted or injected into terminal streams without explicit user initiation |
| Sensitive credential disclosure in terminal session recordings and cast logs | Automated sensitive data redaction engine; mask private keys, tokens, passwords, and MFA codes prior to persistent storage or cast export; opt-in recording; local-only storage by default | Implemented: `SessionRedactor` automatically sanitizes PEM private keys (`BEGIN ... PRIVATE KEY`), bearer authorization tokens (`Bearer ...`), AWS secret keys (`AKIA...`), GitHub/GitLab personal access tokens (`ghp_...`, `glpat-...`), configuration assignments (`password=`, `token=`, `secret=`, `api_key=`), and one-time MFA/TOTP codes (`[0-9]{6}`); recording is strictly user-opted (`⏺ Record` button / CLI import); session casts stored in local SQLite database without automatic cloud sync; users advised that redaction is heuristic and sensitive commands should avoid echo where possible |

Do not store credentials in configuration or logs. No security guarantee is
made for the current foundation, and cross-platform behavior remains untested.
