# Initial threat model

This document is preliminary; no security-sensitive Shellumi subsystem has
been reviewed or approved for production. Revisit it with each design change.

| Threat | Required control | Current status |
| --- | --- | --- |
| Host-key substitution | Verify known keys; explicitly confirm unknown keys; reject changed or revoked keys | System OpenSSH launched with `StrictHostKeyChecking=ask`; pure Rust `known_hosts` verification engine (`shellumi-core::known_hosts`) implements strict matching, TOFU detection, changed-key MITM risk alerts, and `@revoked` key rejection with automated tests |
| Stolen local or synced data | OS-protected keys and authenticated encryption; no plaintext secrets or sync | Credentials excluded from SQLite metadata storage; generated Ed25519 private keys and in-memory secrets (`SecretString`) use `zeroize::Zeroizing` to wipe memory buffers on drop; secrets are strictly redacted in `Display` and `Debug` implementations; multi-platform secure credential storage implemented via `CredentialStore` interface: macOS Keychain (`MacOsKeychainStore` via Apple Security Framework), Windows Credential Manager (`WindowsCredentialManagerStore`), Linux Secret Service (`LinuxSecretServiceStore`), and fallback `EncryptedFileCredentialStore` (AES-256-GCM AEAD, PBKDF2-HMAC-SHA256, atomic file commits, in-memory zeroization), routed automatically via `default_credential_store()`; OAuth tokens are persisted securely in native stores via `OAuthTokenBundle::save_to_store` |
| Malicious terminal output | Bound resource use; gate clipboard, hyperlinks and unsafe control sequences | Initial terminal parser and bounded output queue exist; security review and malicious-output tests are outstanding |
| Untrusted host configuration | Validate persisted and imported records; pass process arguments separately | Core validates destinations; CLI and GPUI dispatch to OpenSSH with explicit argv, `--`, and no shell evaluation |
| Malicious imports or filenames | Validate structure, size and paths; avoid shell interpretation | RFC 4180 CSV and OpenSSH client config parsers validate all destination fields, enforce structure limits, and reject invalid records without shell evaluation |
| Accidental service exposure via SSH tunneling | Warn on public/wildcard bind addresses before creating forwarded ports | Port forward rules check `is_exposed_beyond_localhost()`; CLI emits explicit security warning when binding to non-localhost addresses; default binding strictly 127.0.0.1 |
| Directory traversal or unsafe file writes in SFTP | Normalize paths, validate breadcrumb navigation, reject null bytes and control characters, enforce conflict resolution | `PathUtils` normalizes `..` components and prevents path escapes; transfer paths reject empty strings and control characters; transfers record audit history in database; conflict strategies (overwrite, skip, rename) defined |
| OAuth token theft, sync replay, and ciphertext transposition | Protected tokens, state validation, authenticated versioned records, unique nonces, and bound associated data | Implemented: RFC 7636 PKCE code challenge and CSRF state validation in `shellumi-core::sync`; ephemeral loopback OAuth callback listener (`OAuthCallbackListener`) with token expiration checking (`OAuthTokenBundle`); secure token persistence in OS credential stores (`OAuthTokenBundle::save_to_store`, `load_from_store`, `delete_from_store`) preventing plaintext disk leakage; zero-knowledge AES-256-GCM authenticated encryption envelopes with unique salt and nonce per record; bound associated data (`entity_type:object_id`) preventing record transposition attacks; incrementing version counters and deletion tombstones with three-way conflict detection (`determine_sync_action`); payload-decrypting difference engine (`diff_sync_records_with_passphrase`); PBKDF2-HMAC-SHA256 key derivation with memory zeroization on drop |
| Unsafe automation and snippet injection | Preview and explicit confirmation; isolate secrets and validate substitution | Implemented: `shellumi-core::snippet` escapes parameters with POSIX single-quote rules (`shell_escape`), detects sensitive variable names (*pass*, *secret*, *token*, *key*), redacts secrets in preview (`render_preview`), and requires explicit user action ("Paste" or "Run") in GPUI and explicit `--var` substitution in CLI before sending to terminal PTY |
| Unauthorized collaboration | Authenticate participants, enforce roles and audit cryptographic protocol | Not designed |

Do not store credentials in configuration or logs. No security guarantee is
made for the current foundation, and cross-platform behavior remains untested.
