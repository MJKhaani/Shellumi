# Requirement Migration Inventory

This inventory maps every section of the original master specification ([`master-project-specification.md`](../../archive/implementation-plans/master-project-specification.md), `3123db2:PROJECT.md`) to stable `REQ-*` identifiers, current authoritative destinations, independent implementation status, verification level, source evidence, and acceptance criteria.

> **Honesty Rule:** Implementation status and verification level are tracked separately. An implemented feature can still be `NOT TESTED` interactively on Windows/Linux or against live external servers. No requirement is marked `Implemented` when any of its sub-requirements remain `Partial` or `Planned`—those are decomposed into child IDs (`a`, `b`, `c`).

## Status & Verification Legends

- **Implementation Status:** `Implemented`, `Partial`, `Experimental`, `Planned`, `Unsupported`, `Deprecated`, `Superseded`
- **Verification Levels:** `Source-inspected`, `Unit tested`, `Integration tested`, `Rendered GPUI tested`, `CI verified`, `Native GUI verified`, `Live protocol tested`, `NOT TESTED`
